# 04 · 解法 Playbook（指标体系 → 三阶段 → 方法论 → 验证）

## 第 1 步｜先定义「问题解决」的标准

含糊的问题定义会产出含糊的方案。写清楚：

```
问题定义：<当前状态> → <目标状态>，以 <指标> 达到 <阈值> 为验收。
```

示例：
```
问题定义：试用租户在 7 日内完成建档的比例 <目标线>，且建档后 7 日回访率低。
        以「周活跃激活租户数（WAAT）」在 12 个月内提升 35pt 为验收。
```

## 第 2 步｜建指标体系（三层）

| 层级 | 作用 | 数量 | 示例 |
|---|---|---|---|
| **北极星指标** | 全团队对齐的唯一目标，必须同时反映用户价值与商业价值 | 1 个 | 周活跃激活租户数（WAAT） |
| **驱动指标** | 能撬动北极星的先行指标，对应方案动作 | 3–5 个 | 建档完成率、首单时长、协作席位激活率 |
| **健康指标** | 防止为冲指标而伤害体验 | 2–3 个 | 次周留存、工单率、NPS、退款率 |

**北极星优先复用产品方已有口径**（如官方种子用户标准），这样方案天然与对方 KPI 对齐，而不是另起一套。

指标必须满足：**可观测、可归因、有基线、有目标值**。四个缺一个就不是指标，是口号。

出图：**指标树图**（北极星在上，驱动与健康在下一层，各自挂到具体动作）。

## 第 3 步｜三阶段规划（3 / 6 / 12 个月）

每阶段固定 6 项，缺一项就不算完整方案：

| 项 | 说明 |
|---|---|
| 阶段目标 | 一句话，可验收 |
| 关键动作 | 3–5 条，具体到「做什么、在哪做」 |
| 里程碑 | 有明确交付物与时间点 |
| 达成效果预估 | 指标从 X 到 Y（标注为预估） |
| 配合部门 | 具体到部门名 |
| 资源投入 | 人力 / 预算区间（标注为预估） |

阶段划分的通用逻辑：

- **3 个月（0 → 1）**：先修断崖。用最小改造验证「问题定义对不对」。目标：+8pt 级别
- **6 个月（1 → 10）**：把有效动作体系化，加入分层运营与生命周期管理。目标：+18pt 级别
- **12 个月（10 → 100）**：全链路 + 飞轮（裂变、生态、内容），形成自增长。目标：+35pt 级别

每阶段都要写 **Non-goals**：本阶段明确不做什么。防止范围蔓延。

## 第 4 步｜方法论映射（每阶段显式标注）

| 方法论 | 解决什么 | 用在哪个阶段 | 典型动作 |
|---|---|---|---|
| **AARRR** | 大盘增长，全链路看漏斗 | 3 月（盯 Activation）+ 12 月（全链路 + Referral） | 按 Acquisition→Activation→Retention→Revenue→Referral 排动作优先级 |
| **RFM** | 存量分人群，精细化触达 | 6 月 | 按最近使用 / 频次 / 建档深度给租户打分分层，不同层不同话术 |
| **CLM** | 全生命周期管理 | 6 月 | 定义「引入 → 上手 → 激活 → 试用期管理 → 转化 → 续费 → 流失挽回」各阶段目标与触点 |
| **5A** | 品牌内容种草 | 6–12 月 | 认知 Aware → 吸引 Appeal → 问询 Ask → 行动 Act → 拥护 Advocate，配内容资产 |

映射要具体，写「用 RFM 把租户按建档深度分成 L0–L3 四层，L1 层主推 AI 初始化」——不要只写「使用 RFM 模型」。

## 第 5 步｜验证方案有效性

| 方法 | 适用 | 要点 |
|---|---|---|
| **A/B 测试** | 有足够流量 | 明确实验单元、样本量、显著性水平、观察周期、成功判据 |
| **前后对比** | 流量不足 | 需控制季节性与外部事件干扰，说明局限 |
| **小范围灰度** | 高风险改动 | 先选 1–2 个渠道或企业规模试点，验证后放量 |

每条方案都要回答：**怎么知道它有效？多久能看出来？看哪个指标？** 三个都答不上来，这条方案就不该写进去。

## 第 6 步｜指标监测体系示例图

出四层图（`.diagram`）：

```
采集层：埋点事件 / 业务库 / 客服工单 / 渠道回传
   ↓
加工层：指标口径定义 / 分层标签 / 漏斗聚合
   ↓
看板层：北极星看板 / 激活漏斗看板 / 渠道 ROI 看板 / 分层健康看板
   ↓
决策层：周会复盘 / 渠道预算调拨 / 实验结论入库 / SOP 更新
```

同时给**关键指标监测表**：指标名 / 口径定义 / 数据来源 / 更新频率 / 责任人 / 预警阈值。

## 第 7 步｜落地路径与 RACI

每个阶段出一张 RACI：

| 动作 | R 负责 | A 拍板 | C 咨询 | I 知会 |

常见部门名（按实际情况填）：产品、研发、测试、数据、增长/运营、市场品牌、渠道商务、销售、客服/实施、财务、法务合规。

**资源投入预估**要给区间而非单点，并说明构成（人力人月 + 外部投放 + 工具采购）。

## 第 8 步｜运营体系配套四张表（含 JD 职责的直接落点）

这四张表是「运营岗 JD」最常点名要的交付物，也是报告里最能体现体系化能力的地方。

### 表 1｜试用分层 × 运营策略矩阵
| 分层 | 判定条件 | 运营目标 | 触达方式 | 关键指标 |
|---|---|---|---|---|
| L0 已注册未登录 | 注册后未登录 | 促成首次登录 | 短信/邮件/企微 | 首登率 |
| L1 浅层试用 | 登录但未完成建档 | 引导完成关键动作 | 站内引导 + 人工 | 建档完成率 |
| L2 深度试用 | 建档但未跨角色 | 促成协作/多角色 | 邀请裂变 | 协作激活率 |
| L3 已激活 | 达到激活标准 | 转化付费 | 权益提示 + 人工 | 付费转化率 |

### 表 2｜渠道追踪与 ROI 评估
| 渠道 | 追踪方式 | 获客成本 | 激活率 | **激活单价** | 结论 |
|---|---|---|---|---|---|
| 关键口径：**激活单价 = 获客成本 ÷ 该渠道激活率**。只认激活，不认注册。 |
警告：若渠道只按注册量结算，会系统性高估效果。

按生命周期阶段列出「触发条件 → 运营动作 → 话术要点 → 责任人」，并给线索评分（A/B/C 三类：A 立即人工跟进，B 自动化培育，C 内容触达）。

### 表 4｜内容资产清单
| 资产类型 | 面向阶段 | 目标用户 | 分发渠道 | 生产节奏 |
|---|---|---|---|---|
案例型 / 解决方案型 / 教程型 / 对比型 / 活动型内容各占什么位置。
