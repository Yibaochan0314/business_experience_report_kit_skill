# 03 · 诊断 Playbook（激活标准 → 漏斗 → 下钻 → 根因分级）

这一段决定报告有没有价值。四步走，不要跳步。

## 第 1 步｜定义激活标准

激活标准 = 「用户做了什么，才算真正用起来了」。

**优先级：复用产品方已有口径 > 自建口径。** 用产品方自己的语言，报告才显得你读懂了业务，而不是套模板。

去哪找官方口径：
- 官网 / 帮助中心的活动规则（如「连续 6 周活跃 = 种子用户」「完成首单」）
- 产品的引导流程终点（引导结束时要你完成什么）
- 版本权益设计（免费版给了什么，暗示什么算核心价值）

无官方口径时，自建标准要满足三条：**可埋点、可归因、与付费意愿相关**。

示例（B 端 SaaS）：
```
激活 = 完成基础数据初始化（建档）AND 在 7 日内产生 ≥1 条真实业务数据
```

把「激活」前拆成 4–5 个环节，作为漏斗骨架。

## 第 2 步｜搭漏斗，定位最大断崖

标准漏斗（按产品调整）：

```
触达/访问  →  注册  →  首次登录  →  完成建档/关键动作  →  激活  →  付费
```

画图时**必须做三件事**：
1. 标每环节绝对量与相对上一环的比率
2. **标出最大断崖**（比率跌幅最大的那一段），这是全报告的火力焦点
3. 图注写明数据口径——推演值必须写「基于公开信息的推演值（非官方数据），需接入真实埋点校准」

一个重要的读法：**如果「建档之后到激活」的跌幅很小，说明产品本身能留人，问题高度集中在入口。** 这个判断会直接决定你的方案重心放在「引导」还是「产品价值」。别忽略它。

## 第 3 步｜在最大流失环节做多维下钻

在**最大断崖那一环**上，做三个维度交叉：

| 维度 | 怎么切 | 要回答的问题 |
|---|---|---|
| **行为分层** | 按用户在断崖环节的行为强度分层（如：只登录未建档 / 建档中途中止 / 建档完成但无后续） | 他们在哪一步停手？停手前做了什么？ |
| **来源分层** | 按获客渠道切（广告 / 生态导流 / 裂变 / 地推 / 自然流量） | 哪个渠道来的人流失最严重？ |
| **定量 + 定性** | 定量看比率，定性看用户原声（社区抱怨、客服工单、应用商店评论） | 用户自己说的原因，和数字指向的是同一件事吗？ |

**定性这一栏最容易被跳过，但它常常直接给出根因。** 真实的社区吐槽（「这个功能找不到」「要填的东西太多了」「怎么加同事」）比任何假设都硬。

下钻产出：一张「行为分层 × 来源分层」的交叉热力表，标出最差的那一格——那一格就是你要服务的用户群。

## 第 4 步｜输出根因并按优先级分级

根因表字段（固定五列）：

| 编号 | 根因 | 影响面 | 证据 | 级别 |
|---|---|---|---|---|
| R1 | … | 影响哪一环、影响多少人 | 实测截图 / 文档 / 用户原声（标明） | P0/P1/P2 |

分级标准：

- **P0**：直接卡住激活，且影响面最大。不解决，其他优化都白做
- **P1**：显著影响转化或留存，有明确解法
- **P2**：体验瑕疵或长期优化项

**P0 占比建议 ≤ 40%**。全是 P0 等于没有优先级。

最后写结论句，必须填满三个空：

> **以「[用户身份]」为主的目标用户，在「[具体环节]」流失，因为「[根因 A] × [根因 B] × [根因 C]」三者叠加。**

## 常见根因库（按产品类型，用作自查清单）

**B 端 SaaS / 企业软件**
- 价值兑现后置：要求先做枯燥高门槛的事（建档、导入）才能看到价值
- 协作能力与付费绑定：最能体现价值的多人协作被锁在付费墙后
- 组织架构为空：注册后是「0 部门 0 岗位」，不会自发去搭 HR 流程
- 引导「讲功能不讲任务」：引导很多但看完系统依然空的
- 降门槛功能藏错入口：AI 初始化 / 模板导入这类抓手只出现在某个二级页
- 到期不降级：试用到期后权限照旧，缺乏付费紧迫感
- 生态是愿景：宣称的生态协同尚未上线，用户按宣传来却找不到

**C 端工具 / 内容产品**
- 首次价值时刻（time-to-value）过长
- 注册墙前置：还没看到价值就被要求注册
- 冷启动无内容：空态没有推荐内容兜住
- 通知/召回缺失：离开后无再触达

**交易/平台类**
- 供给或需求任一侧不足导致双边失衡
- 信任成本高（缺担保、缺评价、缺案例）
- 首次交易门槛（资质、押金、审核）

## 一个必须做的动作：让证据推翻你的假设

如果你的假设最初建立在「文档推测」上，而后续获得了实测证据，**必须改写结论，并把改写过程写进报告**。

标准写法：

> 初版判断为「X」，依据为帮助中心文档。实机验证后发现「非 X，而是 Y」——证据是 [截图/行为]。此修正过程说明：文档口径与实机能力可能不一致，结论需以实测校准。

这一条对求职场景价值极高——它证明你在做分析而非填表。**不要把修正痕迹抹掉。**
