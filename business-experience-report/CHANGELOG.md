# 变更记录

记录本 skill 的版本变更，**只增不改**：新版本追加在最上方，不修改历史条目。

当前版本以 `SKILL.md` frontmatter 的 `version` 字段为准。本文件随 skill 一起分发，接收方可据此判断自己装的是哪一版、要不要更新。

> ⚠️ **本文件是历史记录，不是行为规则。** 下方旧版本条目里描述的流程（例如「登录受阻时声明未实测后继续产出」）**已经作废**，仅用于追溯改了什么。**当前该怎么执行，一律以 `SKILL.md` 与 `references/` 为准**；两者冲突时，前者优先。

## 1.2.4 — 2026-10-16

### 变更

- **新增 `README.md`**——面向**使用者**的技能自述：它解决什么问题 / 什么时候别用 / 五类输入与降级 / 交付契约 / 报告三章结构 / 触发语示例 / 两道强制闸门 / 目录结构 / 运行依赖 / 安装与更新 / 常见问题。**内容不重复 `SKILL.md`**：后者写给执行者（工作流与红线），前者写给人（怎么装、怎么用、拿到什么）。
- **`SKILL.md` 第 224 行命令修正**：`agent-browser eval --file scripts/audit_visual.js` → `agent-browser eval --stdin < scripts/audit_visual.js`。

### 动机

`--file` 的上一次修正（1.2.3）**只改了 `scripts/audit_visual.js` 的文件头注释，漏了 `SKILL.md` 正文里同一处错误**。于是同一份技能一半修好、一半留着，而 CHANGELOG 已宣称「已修正」——属于「记录说改了、正文没改全」。本次把正文补齐；同时补一份 README，让接收方不必读 `SKILL.md` 也能上手。

**可复用教训**：修一处用法错误时，必须**全量 grep 同类写法**（不限当前文件），否则会漏掉同一错误的其它落点。

### 验证

- `SKILL.md` frontmatter `version` = `1.2.4`；本条目位于 CHANGELOG 顶部，历史条目未改动。
- `grep -rnE 'eval --file'` 在 `SKILL.md` 与 `scripts/` 内**应为 0 命中**（CHANGELOG 的历史条目保留原写法，用于追溯，不算残留）。
- 四方对账：skill 源 / 仓库副本 / 快照 v1.2.4 / 打包 zip，逐文件 MD5 一致。
- 敏感扫描：`README.md` 是新增的对外文档，按九类清单一并扫描，全部 0 命中。

## 1.2.0 — 2026-10-16

### 新增

- **版本管理机制（三件套）**
  - `SKILL.md` frontmatter 新增 `version` 字段，当前版本以此为准
  - `CHANGELOG.md`（本文件）：记录每次变更的「改了什么 / 为什么改 / 怎么验证的」，只增不改
  - `scripts/snapshot.sh`：读 `version` 后把 skill 完整复制到快照目录，供日后 diff 与回滚；同日同版幂等
- `SKILL.md` 新增「维护与版本管理」一节：明确改动后的三步动作与三点约定

### 动机

在此之前，本 skill **没有版本号、没有 git、没有备份**。直接后果是：「新版是否包含旧版的全部内容」这类问题只能靠回溯对话记录来回答——属于间接证据，且记录一旦被清理就永远无法回答；改动一旦出问题也没有任何退路。补上这层机制：**版本号解决「可验证」，快照解决「可回滚」。**

### 说明

`1.0.0` 与 `1.1.0` 为**回溯补记**——两次改动都发生在版本管理机制建立之前，没有对应的快照文件。`1.2.0` 是机制生效后留档的第一版。

### 验证

- 快照脚本幂等：同日同版重复执行返回「已存在」，不重复留档
- 快照与 skill 目录逐文件 MD5 一致（15 / 15）；快照内无 `.DS_Store` / `__pycache__` 混入
- 负向 1：`SKILL.md` 缺 `version` 字段时，给出可读报错并 `exit 1`
- 负向 2：`version: "9.9.9"`（带引号）能正确解析为 `9.9.9`，快照目录名不含引号
- `quick_validate.py`：Skill is valid!

### 修复（同版本内，1.2.0 未对外分发）

- `snapshot.sh` 原写法在 `set -euo pipefail` 下，`grep` 找不到 `version` 会直接终止脚本，导致「找不到 version」的报错分支永远执行不到——用户只看到**静默退出**，无从判断哪里错了。改为 `grep ... || true` 兜住后再判空。该问题由负向测试暴露，未流出到分发版本。

## 1.1.0 — 2026-10-16（回溯补记）

### 新增

- **两道强制闸门**（`references/08-screenshot-request-and-review.md`）
